# Sway 1.12 PPA for Ubuntu 26.04 — Design

**Date:** 2026-07-02
**Status:** Approved

## Goal

Publish a Launchpad PPA that provides **Sway 1.12** for **Ubuntu 26.04 (resolute)**,
which otherwise ships only Sway 1.11. Installable via `apt` after adding the PPA.

## Key constraint

Sway 1.12 requires **wlroots 0.20.0**. Ubuntu 26.04 ships sway 1.11 paired with
**wlroots 0.19**. Therefore the PPA must provide **two** source packages: wlroots 0.20
*and* sway 1.12.

wlroots ships as a SONAME-versioned shared library, so `libwlroots-0.20` coexists with
the archive's `libwlroots-0.19` without conflict.

## Scope

- Target series: **resolute (26.04) only**. (Noble/24.04 explicitly out of scope for now.)
- Architecture: amd64 primary (arm64 may be enabled later on the PPA).
- Real Launchpad PPA: signed source packages uploaded; Launchpad builders compile them.
- User's Launchpad account, GPG key, and PPA are already set up.

## Approach

**Rebase Ubuntu's existing 26.04 packaging onto the new upstream releases** (Approach A):
take the distro `debian/` packaging as the base, drop in the new upstream tarball, bump
versions, and fix what breaks. Lowest-risk path to native-quality packages.

Prior art for reference (not forked): [luispabon/sway-ubuntu](https://github.com/luispabon/sway-ubuntu),
[samoilov-lex sway PPA](https://launchpad.net/~samoilov-lex/+archive/ubuntu/sway).
No existing PPA currently provides sway 1.12 for resolute.

## Working layout

```
sway-ppa/
  wlroots/        # debian/ packaging + notes for wlroots 0.20
  sway/           # debian/ packaging + notes for sway 1.12
  README.md       # the build+upload runbook
  docs/superpowers/specs/...
```

Upstream tarballs and built artifacts stay out of git (`.gitignore`).

## Components

### wlroots 0.20 source package

1. `pull-lp-source wlroots resolute` — get the 0.19 packaging as the base.
2. Import upstream **wlroots 0.20.0** tarball (gitlab.freedesktop.org).
3. **SONAME rename**: `libwlroots-0.19` → `libwlroots-0.20` in `debian/control`,
   `debian/*.install`, and binary package names. Update/regenerate the `.symbols`
   file (or relax it) for the new ABI.
4. `debian/changelog` → `0.20.0-0ppa1~ubuntu26.04.1`, series `resolute`.
5. Refresh or drop quilt patches that no longer apply.
6. Add any new build-deps 0.20 introduces (color-management era: `libdisplay-info-dev`,
   newer `wayland-protocols`, `hwdata`, etc.), discovered during the first local build.

Produces: `libwlroots-0.20`, `libwlroots-0.20-dev` (+ any common package).

### sway 1.12 source package

1. `pull-lp-source sway resolute` — 1.11 base.
2. Import upstream **sway 1.12** tarball.
3. Bump build-dep to `libwlroots-0.20-dev (>= 0.20)`.
4. `debian/changelog` → `1.12-0ppa1~ubuntu26.04.1`, series `resolute`.
5. Refresh patches.

Produces: `sway`, `sway-backgrounds`, etc.

## Build & test workflow (local, before any upload)

1. Create a resolute sbuild chroot (`mk-sbuild resolute`).
2. Build **wlroots** with `sbuild`; fix build failures (deps/patches) iteratively.
3. Build **sway** with `sbuild`, feeding it the freshly-built wlroots `.deb`s via
   `--extra-package=` (the PPA does not have them yet).
4. **Runtime test**: install both sets of `.deb`s in a resolute container/VM; confirm
   `sway --version` reports 1.12 and that it launches (headless via
   `WLR_BACKENDS=headless` suffices to prove the wlroots link is correct).

## Upload workflow

Build order matters both locally and on Launchpad, because sway depends on wlroots.

1. `debsign` the `.changes`, then `dput` **wlroots first**.
2. Wait for wlroots to build and publish in the PPA.
3. `dput` **sway** — Launchpad resolves `libwlroots-0.20-dev` from the same PPA.

## Versioning & maintenance

- Scheme `<upstream>-0ppa1~ubuntu26.04.1` sorts below any future official Ubuntu
  package, so users upgrade cleanly when 26.04 eventually ships a newer sway.
- `README.md` runbook documents the full rebase → build → test → upload cycle so future
  bumps (1.12.1 / 0.20.1) are mechanical.

## Risks

- **Primary risk:** wlroots 0.20's new build-deps and patch refreshes. Resolved by
  iterating on local `sbuild` output before uploading.
- If a required build-dep is itself too old in resolute, it would need packaging too.
  Considered unlikely on a fresh 26.04; confirmed at first build.
