# Sway 1.12 PPA Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish Sway 1.12 (with its required wlroots 0.20) to the Launchpad PPA `ppa:pgentili/sway` for Ubuntu 26.04 (resolute), tested locally before upload.

**Architecture:** Rebase Ubuntu 26.04's existing `wlroots` and `sway` Debian packaging onto the new upstream releases (wlroots 0.20.0, sway 1.12), bumping versions and fixing what breaks. Build and runtime-test both packages locally with `sbuild` before uploading source packages to Launchpad, which compiles them. wlroots is built and uploaded first because sway build-depends on it.

**Tech Stack:** Debian packaging (debhelper, quilt), `ubuntu-dev-tools` (`pull-lp-source`, `mk-sbuild`, `uscan`), `sbuild`/`schroot`, `devscripts` (`dch`, `debuild`, `debsign`), `dput`, GnuPG, Launchpad.

## Global Constraints

- Target series: **resolute (26.04) only**.
- Architecture: **amd64**.
- wlroots upstream **0.20.0**, package version **`0.20.0-0ppa1~ubuntu26.04.1`**.
- sway upstream **1.12**, package version **`1.12-0ppa1~ubuntu26.04.1`**.
- Changelog/maintainer identity and signing key: **`Paolo Gentili <paolo@pgentili.com>`**.
- Upload target: **`ppa:pgentili/sway`**.
- Build & upload order: **wlroots first, then sway**.
- Local test uses freshly-built wlroots `.deb`s via `sbuild --extra-package=`; Launchpad resolves them from the PPA once wlroots is published.
- **sbuild invocation (resolute):** sbuild defaults to `unshare` mode and ignores the `mk-sbuild` schroot, so all `sbuild` commands must force schroot mode and run under the `sbuild` group, e.g. `sg sbuild -c 'sbuild --chroot-mode=schroot -d resolute --arch=amd64 --chroot=resolute-amd64 <dsc>'`.

## File Structure

```
sway-ppa/
  wlroots/                 # git-tracked copy of the wlroots debian/ packaging (0.20)
  sway/                    # git-tracked copy of the sway debian/ packaging (1.12)
  build/                   # working area: source trees, orig tarballs, .deb output (gitignored)
  README.md                # build + upload runbook
  docs/superpowers/specs/  # design spec
  docs/superpowers/plans/  # this plan
```

Only the `debian/` packaging (under `wlroots/` and `sway/`) is committed. All upstream
tarballs and build artifacts live under `build/` and are gitignored (already covered by
`.gitignore`; a `build/` entry is added in Task 1).

- [ ] **Step 1: Install packaging tooling**

```bash
sudo apt update

  quilt dput gnupg lintian
```

- [ ] **Step 2: Create the GPG key for paolo@pgentili.com**

Run:
```bash
gpg --full-generate-key
```
Choose: `(1) RSA and RSA`, `4096` bits, no expiry (or your preference), real name
`Paolo Gentili`, email `paolo@pgentili.com`. Then capture the key ID:
```bash
gpg --list-secret-keys --keyid-format=long paolo@pgentili.com
```
Expected: a `sec` line like `sec rsa4096/ABCD1234EF567890 ...`. Note the long key ID
(the part after `rsa4096/`).

- [ ] **Step 3: Register the key with Launchpad**

Run:
```bash
gpg --keyserver keyserver.ubuntu.com --send-keys <KEYID>
gpg --armor --export paolo@pgentili.com
```
Copy the armored block, go to <https://launchpad.net/~pgentili/+editpgpkeys>, paste, and
submit. Launchpad emails an encrypted confirmation — decrypt it and follow the link.
Expected: the key shows as confirmed under your Launchpad OpenPGP keys.

- [ ] **Step 4: Configure sbuild for your user and build the resolute chroot**

Run:
```bash
sudo sbuild-adduser "$USER"
newgrp sbuild   # or log out/in so group membership takes effect

```
`mk-sbuild` on first run opens an editor for its config — save and exit to accept
defaults, then re-run `mk-sbuild resolute`. Expected: `schroot -l` lists a
`resolute-amd64` (or `source:resolute-amd64`) chroot.

Run:
```bash
schroot -l | grep resolute
```
Expected: at least one `resolute-amd64` entry.

- [ ] **Step 5: Create the build working dir and gitignore it**

Run:

```bash
grep -qxF 'build/' .gitignore || echo 'build/' >> .gitignore
```

### Task 3: Rebase wlroots packaging to 0.20 and build locally

**Files:**
- Modify (in `build/wlroots-0.20.0/debian/`): `control`, `changelog`, `*.install`,
  `*.symbols` (if present), `patches/*`
- Create: `wlroots/` (committed copy of the finished `debian/`)

**Interfaces:**
- Consumes: `build/wlroots-0.20.0/` from Task 2.
- Produces: built `libwlroots-0.20*.deb` and `libwlroots-0.20-dev*.deb` under `build/`;
  committed `wlroots/debian/` packaging.

- [ ] **Step 1: Identify the binary package names to rename**

Run (from `build/wlroots-0.20.0`):
```bash
grep -E '^Package:' debian/control
```
Expected: lists the current binaries, e.g. `libwlroots-0.19`, `libwlroots-0.19-dev`
(names may include a suffix — use whatever is shown). Record the exact old names.

- [ ] **Step 2: Rename the SONAME-versioned packages 0.19 → 0.20**

In `debian/control`, rename every `libwlroots-0.19*` binary package to `libwlroots-0.20*`
(keep any suffix, e.g. `-dev`). Rename the matching packaging files:
```bash
cd debian
for f in libwlroots-0.19*; do mv "$f" "$(echo "$f" | sed 's/0\.19/0.20/')"; done
cd ..
grep -rn '0\.19' debian/ || echo "no stray 0.19 references"
```
Fix any remaining `0.19` references the `grep` surfaces in `debian/control`,
`debian/*.install`, and `debian/rules` (e.g. install paths carrying the SONAME).
Expected: no functional `0.19` references remain (changelog history entries are fine).

- [ ] **Step 3: Handle the symbols file**

Run:
```bash
ls debian/*.symbols 2>/dev/null && echo "symbols present" || echo "no symbols file"
```
If a `.symbols` file exists, it was renamed in Step 2; empty its symbol entries (wlroots
does not promise ABI stability) so the build does not fail on symbol diffs — keep only
the header line and the `(arch=...)` package stanza, or delete the file entirely:
```bash
rm -f debian/libwlroots-0.20*.symbols
```
Expected: no `.symbols` file that lists individual symbols remains.

- [ ] **Step 4: Bump the changelog to the PPA version**

Run:
```bash
DEBEMAIL="paolo@pgentili.com" DEBFULLNAME="Paolo Gentili" \
  dch -v '0.20.0-0ppa1~ubuntu26.04.1' -D resolute \
  "New upstream release 0.20.0; SONAME bump to 0.20 for sway 1.12."
```
Expected: `debian/changelog` top entry reads
`wlroots (0.20.0-0ppa1~ubuntu26.04.1) resolute; urgency=medium` with the
`Paolo Gentili <paolo@pgentili.com>` signoff line.

- [ ] **Step 5: Refresh quilt patches**

Run:
```bash
export QUILT_PATCHES=debian/patches
quilt push -a
```
Expected: either "File series fully applied" or all patches apply. If a patch fails:
```bash
quilt push -f          # apply the rest with fuzz/rejects
quilt refresh          # update the failing patch to the new source
quilt pop -a
```
For a patch that is now obsolete (already merged upstream), remove it from
`debian/patches/series` and delete the file. Expected: `quilt push -a` succeeds cleanly.

- [ ] **Step 6: Build wlroots with sbuild (the "test")**

Run (from `build/wlroots-0.20.0`):
```bash
dpkg-buildpackage -S -us -uc -d
cd ..
sbuild -d resolute --arch=amd64 wlroots_0.20.0-0ppa1~ubuntu26.04.1.dsc
```
Expected: build finishes with `Status: successful` and produces
`libwlroots-0.20*_amd64.deb` and `libwlroots-0.20-dev*_amd64.deb`.

- [ ] **Step 7: Fix build failures and rebuild until green**

If the build fails on a missing build-dependency (likely for 0.20's color-management
features — e.g. `libdisplay-info-dev`, newer `wayland-protocols`, `hwdata`), add the
package to `Build-Depends:` in `debian/control`, regenerate the `.dsc`, and rebuild:
```bash
cd wlroots-0.20.0
DEBEMAIL="paolo@pgentili.com" DEBFULLNAME="Paolo Gentili" \
  dch -a "Add <pkg> to Build-Depends for 0.20."
dpkg-buildpackage -S -us -uc -d
cd .. && sbuild -d resolute --arch=amd64 wlroots_0.20.0-0ppa1~ubuntu26.04.1.dsc
```
Repeat until `Status: successful`. Expected: the `.deb`s listed in Step 6 exist.

- [ ] **Step 8: Sanity-check the built package with lintian**

Run:
```bash
lintian wlroots_0.20.0-0ppa1~ubuntu26.04.1_amd64.changes
```
Expected: no `E:` (error) tags. Warnings are acceptable; note anything surprising.

- [ ] **Step 9: Commit the finished wlroots packaging**

Run (from repo root):
```bash
rm -rf wlroots/debian
mkdir -p wlroots
cp -r build/wlroots-0.20.0/debian wlroots/debian
git add wlroots/debian
git commit -m "feat: wlroots 0.20.0 packaging for resolute PPA"
```

- [ ] **Step 5: Build sway with sbuild against the local wlroots 0.20 debs**

Expected: no `E:` tags.

- [ ] **Step 8: Commit the finished sway packaging**

```bash
mkdir -p sway
```

**Interfaces:**
- Consumes: the wlroots `_source.changes` from Task 3.

- [ ] **Step 1: Build a signed source-only package**

```bash
debuild -S -sa -d -k'paolo@pgentili.com'
```
Expected: `../wlroots_0.20.0-0ppa1~ubuntu26.04.1_source.changes` is created and signed
(you may be prompted for the GPG passphrase). `-sa` includes the orig tarball (required

- [ ] **Step 2: Upload to the PPA**

Run (from `build/`):
```bash
dput ppa:pgentili/sway wlroots_0.20.0-0ppa1~ubuntu26.04.1_source.changes
```
Expected: `Successfully uploaded packages.` You should receive a Launchpad
acceptance email shortly after.

- [ ] **Step 3: Wait for the build to finish and publish**

Watch <https://launchpad.net/~pgentili/+archive/ubuntu/sway/+packages>. Wait until
wlroots shows **Published** (not just "Building"/"Pending") for resolute/amd64.
Expected: `libwlroots-0.20-dev` is Published. Do not proceed to Task 7 until then —
Launchpad needs it to build sway.
